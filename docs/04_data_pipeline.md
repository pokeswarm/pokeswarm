# 04. 素材とデータの生成

ゲームデータと素材は、スクリプトで外部のデータから生成する。手作業で書き写さない。

## 1. 全体の流れ

```
PokeAPI ──────┐
              ├─▶ scripts/（生成スクリプト）─▶ data/*.json ─┐
SpriteCollab ─┘                         └─▶ スプライトアトラス ─┤
                                                               ├─▶ ゲーム
手書きの定義（技・派生・ステージ・アンロック・エフェクト）──────┘
```

- 生成スクリプトは何度実行しても同じ結果になるようにする。
- 対象のポケモンは「使用するポケモンの一覧」ファイルで指定する（最初はカントーステージに必要な分だけ）。

## 2. PokeAPI から取得するもの

| データ | 用途 |
|---|---|
| ポケモンの種族値 | ゲーム内ステータスへの変換（`01_game_design.md` 5.1） |
| タイプ | 技の候補の決定 |
| 進化の系統・進化条件 | 進化の設計の参考 |
| 場所ごとの野生ポケモンの出現率（バージョン別） | ステージの雑魚の出現一覧の生成（`01_game_design.md` 7.3） |
| ポケモン名（各言語） | 多言語表示 |
| 技名（各言語） | 多言語表示 |
| 持ち物名（各言語） | 多言語表示 |
| タイプ名（各言語） | 多言語表示 |

- 取得結果はローカルにキャッシュし、PokeAPI に何度も問い合わせない。PokeAPI が公開している静的データ（リポジトリ）を使う方法も検討する。
- 【実装済み】`npm run pokeapi`（`scripts/fetch-pokeapi.ts`）。対象は `data/pokeapi/targets.json`、出力は `data/generated/`（pokemon・moves・items・types・regions。コミットする）。地方は名前だけ（マップの選択で使う）。名前は日本語（かな）と英語。進化の条件は赤・緑の条件を優先する。
- 技の**性能**（威力・効果）は本家の数値をそのまま使わず、サバイバー系の技として手書きで定義する。PokeAPI からは名前だけを使う。

## 3. SpriteCollab から取得するもの

- 取得元: https://github.com/PMDCollab/SpriteCollab
- ポケモンごとに、動作別のスプライトシートと `AnimData.xml`（コマの大きさ・表示時間など）がある。
- 使う動作だけを取り出す（初期案: 待機・歩き・攻撃・被ダメージ・倒れ）。
- 【初期案】雑魚敵として使うポケモンは、歩きだけを取り出した軽い画像を別に作る（`uses: ["enemy"]`、`pipeline.json` の `enemyAnimations`）。全動作を入れると GPU のメモリを1種類あたり約5MB使うため（`02_architecture.md` 10.7・10.8）。プレイアブル・中ボス・ボスは全動作（`uses: ["full"]`）。両方に使うポケモンは両方を作る。
- 8方向のうち、使う向きを決める（初期案: 8方向すべて。容量が問題になれば左右反転で減らす）。
- 1枚の大きな画像（テクスチャアトラス）にまとめ、読み込み回数と容量を減らす。
- `AnimData.xml` の情報を、ゲームで使う JSON に変換する。
- 動作が欠けている・仮の画像のポケモンもあるため、欠けている動作の代わりの表示（例: 攻撃がなければ待機を使う）を決めておく。生成スクリプトは欠けている動作を一覧で報告する。

### 3.1 クレジット
- ライセンスは CC BY-NC 4.0。スプライトごとに作者が異なる。
- SpriteCollab リポジトリ内のクレジット情報から、使用したスプライトの作者一覧を自動生成し、ゲーム内のクレジット画面に表示する。

### 3.2 リポジトリに素材を置くかどうか
- 【決定】（2026年10月20日、作者の判断）取得・変換したスプライト（`public/sprites/`）とクレジット（`credits.json`）をリポジトリに含め、公開版でも表示する。取得時の確認用の報告（`report.json`）は含めない。
- 当初の推奨は「リポジトリには生成スクリプトだけを置き、ビルド時に取得する」だった（権利者からの削除申請があったとき、リポジトリ全体が止められる被害を小さくするため）。削除申請があった場合は、該当するスプライトを消して `npm run sprites` の対象から外す。

## 4. 手書きで定義するデータ

| データ | 内容 |
|---|---|
| 技 | 名前のキー（PokeAPI と対応）、タイプ、効果の部品、強化段階、エフェクトのレシピ |
| 派生 | 「技＋要素 → 派生技」の組み合わせ |
| 固有技 | 「ポケモン＋技 → 固有技」の組み合わせ |
| 持ち物 | 種類（ステータス・タイプ・進化の道具）、効果、枠、出現条件 |
| ステータス変換式 | 種族値 → ゲーム内ステータス |
| 進化 | 進化レベル（ランの長さに合わせて換算） |
| ステージ | 長さ、出現する敵、時間ごとの出現ペース、中ボス・ボス・伝説の候補と出現条件 |
| アンロック・実績 | 条件（監視する出来事と回数）と報酬 |
| 永続強化 | 項目、段階ごとの費用と効果、上限 |
| エフェクト | タイプごとの基本レシピ |

- すべての定義に型（スキーマ）を用意し、生成時・起動時に検証する。

## 5. マップ素材

- 繰り返し対応のタイル画像と、散らすための小物画像を生成して用意する（作者が用意）。
- 時間帯ごとに使うタイルは `data/render/ground.json` で指定する。小物の一覧はステージごとにデータで指定する（小物は未実装）。
- 生成した元画像は `assets/map/<地方>/` に置き、`node scripts/process-map-tiles.ts` で `public/map/<地方>/` のタイルに変換する。

### 5.1 道具のドット絵（自作。2026年10月21日）
- マップの道具（きずぐすり・マグネット・ふしぎなアメ）とアメの箱は、公式の画像を使わず自作の 16×16 のドット絵にした。`data/render/items.json` に、1文字が1ドットの表と色で書く（`.` は透明）。起動時にテクスチャにする（`src/render/PixelArt.ts`）。
- 箱からあふれるアメの数も同じファイル（`candyBurst`: +1 は 4個・+3 は 14個・+5 は 42個）。

### 5.2 技・持ち物・パッシブのアイコン（自作。2026年10月21日）
- 【決定】（作者）プレイ画面の、持っている技・持ち物（当時はパッシブも）は文字ではなく**アイコン**で出す。レベルは **★★☆☆☆** のように、最大のうちどれくらいかを見た目で出す。
- 【決定】（同日、作者）星は小さいと形が崩れるので、**ひし形**にし、アイコンの下に**最大8個を1行で**並べる。**派生（進化）するとひし形の色が変わり、レベルは1から**（タイプの技＝黄・派生技＝青・固有技＝赤。`icons.json` の `pipColors`）。アイコンは 64px（16×16 を4倍）、ひし形は 7×7。
- アイコンは 16×16 の自作のドット絵（`data/render/icons.json`）。技は**出し方ごとの白い絵柄**（一番近い敵へ・向いている方向・近接・周回・ビーム・飛んで戻る・地面・周りに広がる・追いかける・画面じゅう・ゆびをふる）を**タイプの色**の四角に重ね、**枠の色**で タイプの技（黒）・派生技（銀）・固有技（金） を分ける。新しい技を足しても、アイコンを描き足さなくてよい。
- 持ち物は、【決定】（作者。2026年10月21日）**PokeAPI の公式のアイテム画像を縮めたドット絵**にした（自作の絵柄では、どの持ち物か直感的に分かりづらかった）。`npm run item-icons`（`scripts/fetch-item-icons.ts`）が、`data/game/items.json` の持ち物ごとに PokeAPI/sprites の画像を取得し（`scripts/.cache/item-sprites/` に保存）、不透明な部分を切り出して縦横比を保ったまま 14×14 に縮め（ドットごとに元の範囲の色を不透明度で重み付けして平均）、色を10色にまとめて（k 平均法）、`data/render/item-icons.json` に1文字1ドットの表と色で書く。描くときは、角を丸めた四角（タイプのアイテムはタイプの色、ほかは決まった色）の上に重ねて枠を付ける（`itemIconPixels`）。権利表記は同じファイルの `credit`（クレジットに出す。`00` 4章）。
- 前の自作の絵柄（剣・盾・羽 など。`icons.json` の `items`）は、画像が無いときの代わりと背景の色に使う。
- 描くときに組み立てる（`src/render/iconPixels.ts`・`Icons.ts`）。プレイ画面は `HudIcons`（1行目 技・2行目 持ち物、アイコンの下にひし形。パッシブの行は廃止）。レベルアップの候補のカードにもアイコンを出す。文字の一覧は F3 の詳しい表示のときだけ。

### 5.3 ドット調の画面（作者の決定。2026年10月22日）
- 文字: 英数字 Press Start 2P・日本語 美咲ゴシック第2（`public/fonts/`。起動時に読み込む。`src/render/pixelUi.ts` の `loadPixelFonts`）。どちらも 8 ドットの字なので、大きさは 8 の倍数（16・24・32）にする。
- 窓: 原作をまねた白い窓（濃い枠と内側の細い線）と、黒い窓に白い枠。Phaser は `drawWindow`・`pixelButton`（上に乗ると ▶）、DOM は `windowCss`。色は `data/render/ui.json`。
- 配置の決まり（作者の指摘 2026年10月22日: 窓やボタンがばらばらの基準で置かれていた）:
  - 1つの画面は1つの「枠」の中に並べる。枠の中の部品は、枠の幅いっぱいか、枠を等分した幅にそろえ、勝手な幅・勝手な位置に置かない。
  - タイトル: ロゴの幅（`data/render/ui.json` の `titleLayout.frameWidth` まで）を枠にし、左にメニュー、右にログインの窓を同じ幅（`blockWidth` まで）で左右対称に置き、上の端もそろえる。真ん中は `centerGap` 以上空けてピカチュウが歩く。ログインの窓のボタンは窓の幅いっぱいで縦に並べ、高さはメニューのボタンにそろえる（`AccountPanel.place`）。
  - 見出しの行: 左に題名、その右に情報（達成数・所持コインなど）、右の端に戻るボタン。実績・ショップは見出しと列の見出しを上に固定し、一覧だけを動かす。
  - 一覧は1行に1つ（実績: 実績・条件・報酬、ショップ: 強化・ランク・効果・買うボタン）。列の幅は全部の行で同じ。
  - ポケモンの一覧: マスは横だけ枠の幅いっぱいに広げ、下の詳しい欄と左右の端をそろえる（高さは変えない）。
  - 待合室: PC は URL の行・4人の枠・一覧・詳しい欄を全部同じ幅で縦に並べ、下のボタンは右寄せで同じ幅。低い画面は2列で、左の列の部品（URL をコピー・4人の枠・ボタン）は全部列の幅いっぱい、ボタンは列を2等分して列の一番下（右の列の下の端とそろう）。
- プレイ画面の上部: いちばん上に経験値のバー（中に「Lv12」）、その下の真ん中に経過時間（分母なし。伝説戦は残り時間を赤で）、右にもらえるコイン（アイコンと数）、左に技・持ち物のアイコン。HP の数字はプレイヤーの近くのバーがあるので出さない。数字以外の文字は出さない（中ボス・ボスの名前も出さず、HP のバーだけ）。左上の文字は F3 の詳しい表示のときだけ。倒れたときの案内は真ん中の下。
- 技・持ち物のアイコンにマウスを乗せると、詳細カード（名前・レベル・タイプと出し方・次のレベルで増えるもの、持ち物は今の効果）を出す（作者の案 2026年10月22日。PC だけ。タッチでは出さない）。出す場所はマウスの位置ではなく、持ち物の列のすぐ下に固定し、技でも持ち物でも同じ場所に出す（持ち物がまだ無くても、いちばん高い持ち物の列のぶんを空けておくので位置は動かない）。レベルアップの選択中は出さない。
- 画面の外にいる大事なものの方向を、画面の端に矢印で出す（作者の依頼 2026年10月22日。`src/render/EdgeArrows.ts`）。対象は ボス（赤）・中ボス（黄）・伝説（紫）・落ちているふしぎなアメ（青）・ほかのプレイヤー（水色。倒れていると赤で点滅）。矢印は自作のドット絵（`data/render/items.json` の `edge-arrow`・`edge-arrow-diag`、ボスの目印は `edge-boss`）で、白く描いて色を掛ける。ドットが崩れないよう向きは8方向に丸め、90度ずつ回すだけ（斜めは斜め用の絵）。置く場所は、画面の真ん中から対象へ向かう線が画面の端（余白の内側。上は HUD をよけて広め）と交わる所。矢印の少し内側に目印（ボスはドクロ、アメはアメの絵、味方は「2P」など）。大きさ・余白・色は `data/render/ui.json` の `edgeArrows`。レベルアップの選択中とランの終わりは出さない。
- 経験値の玉: 自作のドット絵（小さい玉は青、大きい玉は金。`items.json` の `gem`・`gem-big`）。コインのアイコンも同じファイル（`coin`）。
- レベルアップの選択: 原作の白い窓。カードはアイコン・名前・番号とレベル・増えるもの（新しい技だけタイプと出し方）。残り時間は数字だけ。
- タイトル画面: 黒い窓のロゴと、各画面へのボタン（↑↓ と Enter、またはクリック。前のキー C・F・A・S・O も使える）。ログインの状態は右下の黒い窓。
- タイトル画面の背景（作者の決定。2026年10月22日）: ゲーム画面と同じように、**真ん中でピカチュウが右へ歩き、マップが流れる**。ほかの遊べるポケモン（実装予定のすべて。進化の途中・進化先も）が、ときどき画面の端から現れて横切っていく（ピカチュウには近づかず、上か下を離れて通る。右へ歩くポケモンはピカチュウを追い越す）。メニューは左、ロゴは上、ログインの窓は右下。設定は `data/render/ui.json` の `titleWalk`。
  - その前に試した「映写機のフィルムが交差して流れる」案は、何のゲームか分からないので撤回した（作者）。
- 結果画面: 真っ黒な背景に白い枠の窓。見出し（ランクリア！ など）、項目と値、技、伝説・実績、ボタン。
- ほかの画面（ポケモン選択・ショップ・実績・フレンド・待合室・設定）も、フォントと窓・ボタンの色をそろえた。

## 6. 音楽・効果音

- 最初は 8bit 風の生成音源を作者が用意する。公式の音楽は使わない。
- 使った音源・効果音の出典と利用条件を、ファイルごとに記録し、クレジットに表示する。
- 【決定】（2026年10月21日、作者）**効果音はコードで鳴らす 8bit 音**（ファイルを使わない。音ごとの部品は `data/audio/sfx.json`）、**BGM は作者が用意したファイル**。

### 6.1 BGM のファイルの置き方
- `public/audio/bgm/` に置く。曲の名前とファイルの対応・音量・出典は `data/audio/bgm.json` の `tracks`（`credit` に出典と利用条件を書く）。
- 今の曲の名前（ファイル名）: title（タイトル・ポケモン選択）、route（道路）、forest（森）、cave（洞くつ）、sea（海）、victory-road（チャンピオンロード）、elite-four（四天王）、legendary（伝説戦）、result（結果画面）。どれも `<名前>.ogg`。
- 区間ごとの曲は `run.sections`（`spawn.json` の区間と同じ並び）、画面ごとの曲は `scenes`。
- 形式は ogg（mp3 でもよい。そのときは `file` の拡張子を変える）。曲の終わりから始めへつながるループにしておく。ファイルがまだ無い曲は鳴らさない（エラーにならない）。

### 6.2 コードで鳴らす 8bit の曲（作者の依頼。2026年10月21日）
- 作者の依頼で、BGM も Claude がオリジナルの 8bit 曲として作る。この環境には音声ファイルを書き出す道具（ffmpeg など）が無いため、曲は**楽譜のデータ**（`data/audio/music/<名前>.json`）にし、ブラウザで矩形波・三角波・雑音を組み合わせて鳴らす（`src/audio/music.ts`）。ファイルが要らず軽い。ループもきれいにつながる。
- 楽譜: 1つの記号が1ステップ（16分音符）。音符は C4・F#5・Bb3、"-" で伸ばし、"." で休む。パートは lead（旋律・矩形波）・harmony（分散和音・細い矩形波）・bass（三角波）・drums（k・s・h）。パターンを order の順につなぐ。
- `bgm.json` の曲に `score` を書くと楽譜で鳴らす。`file` も書けばファイルを先に使い、読めなければ楽譜にする（作者がファイルを用意すれば差し替えられる）。
- 公式の曲・そのアレンジは使わない（`00` 4）。旋律はすべて新しく作る。

### 7.1 スプライトの取得・変換（`npm run sprites` → `scripts/fetch-sprites.ts`）
- 対象は `data/sprites/pokemon.json`（使用するポケモンの一覧）、取得元・取り出す動作・欠けたときの代わりは `data/sprites/pipeline.json` で指定する。
- 取得元は SpriteCollab の**特定のコミットに固定**する（`source.ref`）。同じ設定なら何度実行しても同じ結果になる。取得したファイルは `scripts/.cache/` に保存し、再取得しない。
- `AnimData.xml` の `CopyOf`（別の動作の絵を使い回す指定）をたどる。
- 動作が欠けていれば `fallbacks` の代わりをたどり、結果を `public/sprites/report.json` とコンソールに一覧で出す。代わりも無い動作は出力に含めず、ゲーム側は最初の動作で代用する。
- 出力（`public/sprites/<key>/`）: 使うシートを縦に積んだ1枚のアトラス `atlas.png`・Phaser のアトラス形式 `atlas.json`・アニメーション定義 `anims.json`。コマの名前は `<動作>/<方向の番号>/<コマ番号>`。方向の番号は SpriteCollab の行の並び（下, 右下, 右, 右上, 上, 左上, 左, 左下）。1方向しかない動作は全方向で同じ行を使う。
- コマの表示時間は AnimData の値（1/60 秒単位）をそのまま持ち、ゲーム側でミリ秒に直す。
- 作者一覧は各フォルダの `credits.txt` と `credit_names.txt` から `public/sprites/credits.json` に出力する。Discord の ID は連絡先として載せない。
- 出力は `report.json` を除いてリポジトリに含める（3.2）。スプライトが無いポケモンは仮の円で表示する。
