# 04. 素材とデータの生成

ゲームデータと素材は、スクリプトで外部のデータから生成する。手作業で書き写さない。

## 1. 全体の流れ

```
PokeAPI ──────┐
              ├─▶ scripts/（生成スクリプト）─▶ data/*.json ─┐
SpriteCollab ─┘                         └─▶ スプライトアトラス ─┤
                                                               ├─▶ ゲーム
手書きの定義（技・派生・ステージ・アンロック・エフェクト）──────┘
```

- 生成スクリプトは何度実行しても同じ結果になるようにする。
- 対象のポケモンは「使用するポケモンの一覧」ファイルで指定する（最初はカントーステージに必要な分だけ）。

## 2. PokeAPI から取得するもの

| データ | 用途 |
|---|---|
| ポケモンの種族値 | ゲーム内ステータスへの変換（`01_game_design.md` 5.1） |
| タイプ | 技の候補の決定 |
| 進化の系統・進化条件 | 進化の設計の参考 |
| ポケモン名（各言語） | 多言語表示 |
| 技名（各言語） | 多言語表示 |
| 持ち物名（各言語） | 多言語表示 |
| タイプ名（各言語） | 多言語表示 |

- 取得結果はローカルにキャッシュし、PokeAPI に何度も問い合わせない。PokeAPI が公開している静的データ（リポジトリ）を使う方法も検討する。
- 技の**性能**（威力・効果）は本家の数値をそのまま使わず、サバイバー系の技として手書きで定義する。PokeAPI からは名前だけを使う。

## 3. SpriteCollab から取得するもの

- 取得元: https://github.com/PMDCollab/SpriteCollab
- ポケモンごとに、動作別のスプライトシートと `AnimData.xml`（コマの大きさ・表示時間など）がある。
- 使う動作だけを取り出す（初期案: 待機・歩き・攻撃・被ダメージ・倒れ）。
- 8方向のうち、使う向きを決める（初期案: 8方向すべて。容量が問題になれば左右反転で減らす）。
- 1枚の大きな画像（テクスチャアトラス）にまとめ、読み込み回数と容量を減らす。
- `AnimData.xml` の情報を、ゲームで使う JSON に変換する。
- 動作が欠けている・仮の画像のポケモンもあるため、欠けている動作の代わりの表示（例: 攻撃がなければ待機を使う）を決めておく。生成スクリプトは欠けている動作を一覧で報告する。

### 3.1 クレジット
- ライセンスは CC BY-NC 4.0。スプライトごとに作者が異なる。
- SpriteCollab リポジトリ内のクレジット情報から、使用したスプライトの作者一覧を自動生成し、ゲーム内のクレジット画面に表示する。

### 3.2 リポジトリに素材を置くかどうか
- 【要決定】スプライトを GitHub リポジトリに含めるか。
- 推奨: リポジトリには生成スクリプトだけを置き、スプライトはビルド時に取得する。権利者からの削除申請があった場合に、リポジトリ全体が止められる被害を小さくするため。

## 4. 手書きで定義するデータ

| データ | 内容 |
|---|---|
| 技 | 名前のキー（PokeAPI と対応）、タイプ、効果の部品、強化段階、エフェクトのレシピ |
| 派生 | 「技＋要素 → 派生技」の組み合わせ |
| 固有技 | 「ポケモン＋技 → 固有技」の組み合わせ |
| 持ち物・パッシブ | 効果、枠、出現条件 |
| ステータス変換式 | 種族値 → ゲーム内ステータス |
| 進化 | 進化レベル（ランの長さに合わせて換算） |
| ステージ | 長さ、出現する敵、時間ごとの出現ペース、中ボス・ボス・伝説の候補と出現条件 |
| アンロック・実績 | 条件（監視する出来事と回数）と報酬 |
| 永続強化 | 項目、段階ごとの費用と効果、上限 |
| エフェクト | タイプごとの基本レシピ |

- すべての定義に型（スキーマ）を用意し、生成時・起動時に検証する。

## 5. マップ素材

- 繰り返し対応のタイル画像と、散らすための小物画像を生成して用意する（作者が用意）。
- ステージごとに、使うタイルと小物の一覧をデータで指定する。

## 6. 音楽・効果音

- 最初は 8bit 風の生成音源を作者が用意する。公式の音楽は使わない。
- 使った音源・効果音の出典と利用条件を、ファイルごとに記録し、クレジットに表示する。
