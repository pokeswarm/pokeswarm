# 00. 基本方針書

PokéSwarm の目的・体験の柱・守るべき方針をまとめた文書。ほかの仕様書と食い違う場合は、この文書の方針を優先する。

## 1. 概要

| 項目 | 内容 |
|---|---|
| 名称 | PokéSwarm（表記上の英数字名は `pokeswarm`） |
| ジャンル | サバイバー系（Vampire Survivors 型）アクション、最大4人の協力プレイ |
| 題材 | ポケモン（非公式・非営利のファンゲーム） |
| 動作環境 | PC のブラウザ（キーボード操作）。スマホ対応は将来の課題 |
| 公開先 | `pokeswarm.org`（Cloudflare で取得予定・一般公開前に取得） |
| リポジトリ | GitHub 組織 `pokeswarm` / リポジトリ `pokeswarm` |
| 最初の公開版 | カントーステージのみ |

## 2. コンセプト

「進化と、限られた技の枠で組むビルドを、フレンドと一緒に試す」サバイバー系ゲーム。

既存のポケモン系サバイバーゲームとの違い:

- **PokéSurvivor**: ブラウザ・協力プレイ対応だが、ラン中の進化がない。
- **Pokémon Survivor Burst**: ラン中に進化するが、ダウンロード型でソロ中心。初見でもレベルアップの候補を全部取り切れてしまい、ビルドを組んだ実感が薄い。

PokéSwarm は、ブラウザ・協力プレイ・**選択に代償があるビルド構築**の3つを同時に満たすことを目指す。

## 3. 体験の柱

1. **フレンドとの協力プレイ** — フレンドリストから招待して最大4人で遊ぶ。
2. **ビルド構築** — 大量の技候補の中から、限られた枠を埋めていく難しさ。「1ランで全候補の半分も取れない」「選ばなかった道はそのランでは戻れない」を原則とする。
3. **高難易度の突破** — 難しいステージを、ビルドの工夫で乗り越える。永続強化は「少し有利になる」程度にとどめ、本筋はビルドの組み方で決まる。
4. **アンロック** — 実績・撃破数によるポケモンの解放など、1ランごとに何かが進む感覚。

ランキング機能は作らない。

- 名称に「Poké」を使うことは、ファンサイトとして堂々と行う方針で決定済み。
- **ポケモンのドット絵**: SpriteCollab（PMDCollab）を使用する。ライセンスは CC BY-NC 4.0 のため、非営利・作者ごとのクレジット表記が必須。
  - 【決定】SpriteCollab には公式ゲーム（ポケモン不思議のダンジョン）由来のスプライト（作者表記 `CHUNSOFT`）が含まれ、カントーの151匹はすべて該当する。ほかのポケモン題材のサバイバー系ゲームと同様に、これらも使用し、クレジットに「権利は任天堂・クリーチャーズ・ゲームフリーク・株式会社ポケモン・スパイク・チュンソフトに帰属する」旨を明記する。
  - 権利者の許可を得たものではないため、削除の申し入れがあれば速やかに対応する（下記）。
- **ポケモン・技・持ち物の名称やステータス**: PokeAPI から取得する。
- **フォント**: 【決定】（作者。2026年10月22日）画面の文字はすべてドットのフォントにする。英数字は Press Start 2P（SIL Open Font License 1.1。ライセンス文を `public/fonts/PressStart2P-OFL.txt` に同梱）、日本語は原作の 8×8 ドットの文字に近い 美咲ゴシック第2（門真なむ。改変の有無・商用を問わず利用・複製・再配布できるフリーソフトウェア。`public/fonts/misaki-readme.txt` を同梱）。公式のフォントは市販の書体なので使わない。クレジットに `data/render/ui.json` の `font.credits` を出す。
- **持ち物のアイコン**: 【決定】（作者。2026年10月21日）PokeAPI（PokeAPI/sprites）の公式のアイテム画像を元に、低解像度のドット絵（14×14）にして使う（自作の絵柄では直感的に選びづらかったため）。クレジットに「権利は任天堂・クリーチャーズ・ゲームフリーク・株式会社ポケモンに帰属する」旨と出典を明記する（`data/render/item-icons.json` の `credit`・`source`）。マップに落ちる道具（きずぐすり など）は自作のまま。
- **音楽・効果音**: 公式の音楽は一切使わない（アレンジも含む）。最初は 8bit 風の生成音源を使い、使用した素材はすべて出典をクレジットに記載する。
- **マップ素材**: 公式の背景を元にせず、オリジナルとして生成したタイル画像を使う。
- **技のエフェクト**: 画像素材ではなく、パーティクル・図形・動きの組み合わせで自作する。
- 権利者から削除の申し入れがあった場合は速やかに対応する。連絡先をクレジットに載せる。
- 将来の差し替えに備え、**ゲームの仕組みとキャラクターのデータ・素材を分離**して作る（データ駆動）。

## 5. 運営とお金の方針

- 無料・広告なし・課金なし。
- オプション画面で Ko-fi による寄付を呼びかける。寄付はサーバー代・ドメイン代に充てる。
- **寄付はゲーム内の有利に一切つながらない**ことを明記する。寄付者限定の見た目や色違いなども作らない。
- プレイ中に寄付の呼びかけを繰り返し表示しない。
