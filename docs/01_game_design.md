# 01. ゲームデザイン仕様

各項目に次の印を付ける。

- **【決定】** 方針として確定済み。変更する場合は作者に確認する。
- **【初期案】** 仮の値・仮の仕様。実装しやすい形で作り、調整できるようにしておく。
- **【要決定】** まだ決まっていない。実装前に作者に確認する（一覧は `06_roadmap.md`）。

数値はすべてデータファイルで定義し、コードに直接書かない。

---

## 1. ランの流れ

1. ステージとプレイアブルポケモンを選ぶ（協力プレイ時は各自が選ぶ）。
2. 敵の群れを倒し、経験値を集めてレベルを上げる。
3. レベルアップのたびに「技・持ち物」から1つ選ぶ。
4. 一定レベルで進化する。
5. 途中で中ボス（ジムリーダーの相棒ポケモン）が出現する。
6. 制限時間の終わりにステージのボス（四天王かサカキ）が出現する。倒せばランクリア。
7. ランクリア後、確率で伝説ポケモンが乱入する（ボーナス戦）。
8. ラン終了時にコインを獲得し、永続強化に使う。

| 項目 | 内容 |
|---|---|
| ランの長さ | 【決定】ステージごとに決める。簡単なステージは約10分、難しいステージは約30分。ボスの出現タイミングもこれに合わせる |
| 全滅 | 【決定】全員が倒れ、復活可能数も残っていなければラン失敗 |

## 2. 敵

### 2.1 雑魚敵
- 【決定】技を使わない。プレイヤーに触れたときのダメージ（接触判定）のみ。
- 【決定】動きは「一番近いプレイヤーへ向かって進む」を基本とする（同期を軽くするため。`03_network.md` 参照）。
- 【決定】画面外でも存在し続け、プレイヤーから一定距離以上離れた敵は、プレイヤーの進行方向側へ移し替える（Vampire Survivors 型）。
- 【決定】敵の数には「全体の上限」と「プレイヤー1人あたりの上限」を設ける。上限に達したら新しく出さない。
- 【決定】（2026年10月、作者の判断で変更）上限に達したときに既存の敵を強化する仕組み（赤く表示する敵）はやめる。直感的に分かりにくいため。圧力は、時間帯ごとに敵の HP を上げることで保つ（7.3）。
- 【初期案】上限の数値は技術検証（`06_roadmap.md` フェーズ0）の結果で決める。仮の値は全体600・1人あたり400（`data/game/spawn.json`）。技術検証では敵3000体でも描画を含めて60fpsを大きく上回ったため、上限は性能よりも遊びやすさ・同期の通信量で決めてよい（`02_architecture.md` 10.3）。
- 【決定】雑魚敵は近づいてくるだけ（遠距離攻撃・回り込みなどはしない）。
- 【決定】雑魚敵で種類ごとに固有なのは**タイプ**だけ。HP・大きさ・速さ・接触ダメージは、種類によらず時間経過（またはプレイヤーのレベル）に応じて増える。
- ~~【決定】増加の基準は**時間経過**（時間帯）にする。後の時間帯に出る敵ほど HP が多い。原作で後に出るポケモンほどレベルが高い感覚と結びつける（コラッタ・ポッポが出るころは弱く、オニドリル・ドードリオが出るころは強く感じる）。協力プレイでも全員共通で、ホストが決めやすい。~~ → 下の改訂で、HP は**プレイヤーのレベル**で上げる。
- 【決定】（2026年10月21日、作者のテストランを受けて）雑魚の HP は、**序盤は最初の技の一撃で倒せる量**にし、**プレイヤーのレベルに応じて**上げる（時間がたっただけでは固くならない）。倒せる手応えがあるから、団子になった群れに追われてかわす体験が生まれる。【初期案】基本 HP 7、レベル1つごとに +6%、区間の倍率は ×1〜×1.5（`spawn.json` の `hpPerLevelPct`・`waves[].hpMultiplier`）。協力プレイでもレベルは共有なので全員共通。
- 【初期案】HP の倍率は時間帯ごとにデータで定義する（`data/game/spawn.json` の `waves[].hpMultiplier`）。大きさ・速さ・接触ダメージの倍率も同じ形で足す。

### 2.2 中ボス・ボス
- 【決定】中ボス（ジムリーダーの相棒）は技を使わない。HP と大きさが雑魚より大きいことで差別化する。
- 【決定】ボス（四天王・サカキの相棒）: ボス戦の間も雑魚は湧き続ける。ボスはプレイヤーに近づきながら、**範囲技を1つ**だけ使う。
- 【決定】伝説（ランクリア後の乱入）: 雑魚はいなくなり、伝説と戦う。伝説は**4つの技**を使い分ける:
  1. 移動しながらの攻撃（突進など）
  2. 直線の攻撃（ビームなど）
  3. 自分の周りへの範囲攻撃
  4. 場所を指定した範囲攻撃（予告の後に落ちてくるなど）
- 【初期案】伝説の登場時に、残っている雑魚は演出とともに消す（DANGER の演出に合わせる）。
- 【初期案】ボス・伝説の技は、当たる前に範囲を予告表示する（避けられる攻撃にする）。
- 【初期案】ボスの範囲技: 3.5秒ごとに、一番近いプレイヤーの足元と周りに3つの円（半径90）を予告し、1.2秒後に落とす。中ボス・ボスはノックバックを受けず、動きを止める状態異常の時間は 1/4。2人目以降1人につき HP +60%（`data/game/stage.json`）。
- 【決定】強さは参加人数に応じて上げる。
- 【初期案】ジムリーダー（区間の中ボス）を**2人倒すごとに雑魚の HP +15%**（4人目で +30%、8人目で +60%。時間帯ごとの倍率・レベルごとの伸びに掛ける。`spawn.json` の `hpPerTwoGymsPct`。作者の指摘「進化で大味になって爽快だが、ちょっと余裕すぎる」。2026年10月21日）。
- 【初期案】雑魚: 2人目以降1人につき、上限 +1人分（今まで通り）・出現の速さ +100%・HP +20%。経験値は共有なので、雑魚1体の経験値を ÷ (1 + 0.75 × (人数 − 1)) にする（4人で約 1.2倍の速さでレベルが上がる）。全体の上限は 1600体（`data/game/spawn.json` の `perExtraPlayer`・`capGlobal`。作者の指摘「人数に応じた難易度調整が簡単すぎる」。2026年10月21日）。

### 2.3 当たり判定とダメージ
- 【決定】当たり判定の大きさはおおまか（円）でよい。大きさはデータで決める（種類・進化・ボスなどで変える）。
- 【決定】ダメージは「自然な」判定にする。具体的には、**自分に関わることは自分のブラウザで判定する**:
  - 自分の攻撃が敵に当たったか → 攻撃したプレイヤーのブラウザ（`03_network.md` 3.3）
  - 自分が敵に触れてダメージを受けたか、ボスの技が自分に当たったか → 受けたプレイヤーのブラウザ
  - 自分が拾える物に触れたか → 触れたプレイヤーのブラウザ（確定はホスト。3.4）
  画面で見えたとおりに当たる・避けられるので、通信の遅れがあっても理不尽に感じにくい。

## 3. 経験値・レベルアップ・選択

### 3.1 経験値とレベル
- 【決定】経験値とレベルは参加者全員で共有する。
- 【決定】レベルアップは全員同時に起きる。
- 【決定】1ランの終わりの目安のレベルを決めて経験値の配分を作る。永続強化も持ち物も無い状態で、1ラン15分（カントー）の目安は **レベル50**。50でもほとんどのポケモンは進化し終わる（カントーの151匹でレベル50より後に進化するのはカイリュー（55）だけ）。
- 【決定】永続強化・持ち物（しあわせタマゴなど）・上振れが重なると **レベル70〜100（上限）** 近くまで上がり、ランクリア後の伝説とも戦えるくらいになる想定。
- 【初期案】必要な経験値の表と、敵が落とす経験値（時間帯ごとの倍率）は `data/` で定義し、シミュレーションだけを速く回す道具で「強化なしで普通に遊んだら1ランで約50」になるかを確かめて調整する（フェーズ1）。

### 3.2 レベルアップ時の選択
- 【決定】レベルアップ中は**全員のゲームを止める**。
- 【決定】全員が選び終えたら再開。制限時間は約15秒。
- 【決定】候補は**プレイヤーごとに別々**に出る。
- 【決定】選択肢の種類は「技を覚える・強化する」「持ち物を得る・強化する」の2種類。パッシブという分け方は、遊んだ感想を受けて廃止した（2026年10月21日。`07` 21章）。
- 【決定】技は持ち物の**2倍の重み**で候補に選ばれる（作者の決定（2026年10月21日。`07` 21章）。`leveling.json` の `moveOfferWeight`）。
- 【決定】「見送る」ボタンを用意する。見送るとリロール権が +1。時間切れも「見送る」と同じ扱い。
- 【決定】再開時に、全員にごく短い無敵時間を付ける。
- 【決定】リロール権は消費して候補を引き直せる。初期数は永続強化で増える。
- 【決定】選択画面は、画面の横幅いっぱいに大きなカードを横に並べる。カードには名前と短い説明（技はタイプと出し方、持ち物は効果）が収まるようにする。
- 【決定】（作者の指摘。2026年10月21日）強化のカードには、**そのレベルで何が増えるか**を書く（強くなった感が分かるように）。技は前のレベルとの差（数 +1・大きさ +2・再使用 −0.1秒 など、良くなったものだけ）と、総合の強さの伸び（強さ +23%）。持ち物は「物理の技の威力 +20% → +30%」のように今と次の値。新しい持ち物も効果を同じ形で出す。
- 【決定】派生の材料などのヒントは極力出さない。「おや……？」の表示は、**その派生（固有技を含む）を以前に一度達成していて、かつそのカードを今取ると条件がそろう**ときだけ出す。文言は原作の進化の前の言葉（日本語「おや……？」、英語「What?」）。ほかの言語を足すときも、その言語版の原作の進化前の言葉にする。
- 【決定】キーは 数字キーで選ぶ、R でリロール、X で見送る（WASD の S と重ねない）。

### 3.3 候補の出し方
- 【決定】技の候補は、選んだポケモンの**タイプ**によって出るかどうかが決まる。
- 【決定】進化でタイプが増えると（例: リザード → リザードンでひこうタイプが追加）、候補の範囲も広がる。
- 【決定】**ノーマルタイプの技は、すべてのポケモンの候補に出る**。
- ノーマルタイプのポケモンは、相手の弱点を突く工夫はできない代わりに、候補に出る技の種類が少ないので、欲しい技を引きやすい（技の強化の再現性が高い）。複数のタイプを持つポケモンは、技の種類が多い分、欲しい技を引きにくい。
- ~~【決定】協力プレイ時、**誰かがすでに持っている持ち物は候補に出さない**。~~ → 【決定】（2026年10月21日、作者が3人で遊んで）**廃止**。ほかの人が持っている持ち物も候補に出る。
- ~~【決定】同じ回のレベルアップで、同じ持ち物が複数人の候補に重複しないようにする（ホストが全員分の候補をまとめて作る）。~~ → 【決定】（2026年10月21日、作者）**廃止**。候補はホストが全員分を作るが、同じアイテムが複数人に出てもよい。

### 3.4 経験値の玉・拾える物
- 【決定】経験値は敵を倒した場所に玉として落ち、拾うと全員で共有する。
- 【決定】経験値の玉は「取得範囲」（ステータス）に入ると吸い寄せられる（Vampire Survivors と同様）。
- 【決定】経験値以外の拾える物（回復・全回収など）は接触したときだけ拾える（吸い寄せない）。
- 【初期案】協力プレイでの取得: 触れたプレイヤーのブラウザが「拾った」とホストへ伝え、ホストが先着で確定して全員へ送る。経験値は共有なので、誰が拾っても結果は同じ（同じ玉を2回数えないことだけホストが保証する）。自分の画面では触れた瞬間に消して見せる。
- 【初期案】玉が多くなりすぎたら、新しい経験値を倒した場所に一番近い玉にまとめる（性能と通信量のため）。まとめられた玉は色を変えて見分けられるようにする。
- 【決定】（2026年10月21日、作者の提案）マップに落ちる道具を3つ用意する。
  - **きずぐすり**: 雑魚がまれに落とす。拾うと HP を回復する。**HP の回復手段は基本的にこれだけ**にする（たべのこし・店の「回復」は外した）。ギガドレイン・やどりぎの回復は技の個性として残す（作者が確認）。
  - **マグネット**: 雑魚がまれに落とす。拾うとマップ上の経験値の玉をすべて一気に吸い寄せる。
  - **ふしぎなアメ**: 中ボスが経験値の代わりに落とす。拾うと演出つきで 1・3・5 レベルのどれかを抽選し、確定でレベルアップする（選択が続けて出る）。
- 【初期案】きずぐすりは雑魚1体あたり 0.06%（作者の指摘で 0.3% から下げた。2026年10月21日）・最大HPの30%回復、マグネットは 0.12%、アメは +1/+3/+5 を 60/30/10 の重み、抽選の演出は 1.2秒、当たりを見せてからレベルが上がるまで 1.2秒（`data/game/pickups.json`）。協力プレイでは、きずぐすりは拾った人だけ回復し、マグネットとアメ（経験値・レベルは共有）は全員に効く。
- 【決定】（同日、作者のテストランを受けて）ふしぎなアメは文字が出るだけでは気持ちよくない。**箱からアメが出る量で当たりを見せる**（+1＝ちょっと出る、+3＝たくさん出る、+5＝大量にあふれ出る）演出にする。道具のドット絵がまだ無いので、フェーズ4（素材と音）で作る。→ 作った（2026年10月21日）: 拾うと頭の上に箱が出て揺れ、当たりが決まると箱が開いてアメが飛び出す（+1 は 4個・+3 は 14個・+5 は 42個）。

## 4. 技・持ち物

### 4.1 技
- 【決定】技を覚えられる枠は有限。「今この技を覚えていいのか」と悩ませる。
- 【初期案】枠は4つ（本家の「技は4つまで」に合わせる）。
- 【決定】**技は忘れられない**。枠が埋まった後は、技の候補は出ず、持ち物・覚えている技の強化から選ぶ。枠が空いているうちは「本当に欲しい技が出るのを待つか、今出た技で枠を埋めるか」を悩ませる。
- 技は自動で発動する。
- 【決定】技はダメージと**貫通可能数**（1つの攻撃が当たれる敵の数）を持つ。近接攻撃は貫通無限（作者指定）。1つの攻撃は同じ敵に1回だけ当たる。
- 【初期案】その場に一定時間残る攻撃（近接・範囲）が同じ敵に当たり直すまでの間隔は、技の仕組み（フェーズ1）で決める。
- 【決定】技の性能は次の項目の組み合わせで定義する（データ）:
  - ダメージ、タイプ、分類（物理・特殊。原作の分類に合わせる）
  - 速さ（発射体の速さ）、範囲（大きさ）、距離（射程）、持続時間
  - 貫通可能数、ノックバック
  - 状態異常（種類・確率・持続時間・強さ。4.6）
  - 派生先と派生の条件（4.2）
- 【初期案】次の項目も加える（Vampire Survivors の武器を再現するのに必要）:
  - 再使用までの時間（クールダウン）、1回に出す数、複数出すときの間隔
  - 同じ敵に当たり直すまでの間隔（その場に残る攻撃用）
  - **出し方**（どこへ・どう出るか）: 一番近い敵へ / 向いている方向へ / ランダムな方向へ / 自分の周りを回る / 自分の周りに常に出る（オーラ）/ ランダムな敵の上に落ちる / 跳ね返る / 敵から敵へ連鎖する / 地面に残る（設置）/ 扇形に広がる / 直線のビーム
  - 跳ね返り回数・連鎖数
  - 急所（会心）の確率と倍率
  - 自分や味方への効果: 回復（いやしのすず等）、吸収（ギガドレイン等で与えたダメージの一部を回復）、一時的な強化（つるぎのまい等）。協力プレイで味方を助ける技はポケモンらしさと協力の楽しさの両方に効く
  - レベルごとの強化表（技を重ねて取ったときに何がどれだけ上がるか）と最大レベル

### 4.2 技の派生（3段階）
1. **タイプの技** — タイプに応じて候補に出る基本の技。
2. **派生技** — 特定の技と特定の要素（主に持ち物）を組み合わせると派生する。
3. **固有技** — 特定のポケモンが特定の技を持つと、そのポケモンだけの固有技に進化する。

- 【決定】上の3段階を持つ。技は最大3段階（タイプの技 → 派生技 → 固有技）。3段階目はポケモン（系統）ごとの固有技という位置づけ。
- 【決定】派生の条件は「元の技が最大レベル ＋ 材料の持ち物を持っている」。条件がそろうと、次のレベルアップの候補に**必ず**（100%）出る（Vampire Survivors の武器の進化と同じ）。派生した技は元の技と入れ替わる（枠は増えない）。
  - 例: ひのこ（最大レベル）＋ もくたん → かえんほうしゃ
- 【決定】派生技の材料は、**元の技のタイプのアイテム**（ひのこ＋もくたん、たいあたり＋シルクのスカーフ）。固有技の材料は、解釈が一致するものか意外なもの（ヒトカゲ＋ほのおのいし、ガーディ＋でんこうせっか＋スピーダー → しんそく）（2026年10月21日。`07` 21章）。
- 【決定】1つの技が2種類以上に派生できる。例: ひのこ ＋ プラスパワー → かえんほうしゃ、ひのこ ＋ ディフェンダー → ほのおのうず（自分の周りを炎が回り続ける）。
- 【初期案】両方の材料を持っていれば両方の派生が候補に出るが、選べるのは片方だけ。選ばなかった派生はそのランでは戻れない（`00_vision.md` の「選ばなかった道は戻れない」）。

- 【初期案】固有技は手作業で設計が必要なため、最初の公開版では一部のポケモンにだけ用意し、更新ごとに増やす。

### 4.3 持ち物
- 【決定】派生技の材料になる。
- 【決定】持ち物の枠は **6つ**（2026年10月21日。`07` 21章）。
- 【決定】持ち物は3種類（2026年10月21日。`07` 21章）:
  - **ステータスのアイテム**（1つのステータスに1つ。プラスパワー＝物理の威力・スペシャルアップ＝特殊の威力・ディフェンダー・マックスアップ・スピーダー・クリティカット・せんせいのツメ＝クールダウン・ポイントマックス＝技の数・こうかくレンズ＝範囲・ひかりのねんど＝持続・メトロノーム＝弾の速さ・ダウジングマシン・しあわせタマゴ）。だれにでも候補に出る。
  - **タイプのアイテム**（そのタイプの技 +15%）。**自分のタイプとノーマル**のものだけ候補に出る。
  - **進化の道具など**（初代の石・つながりのヒモ・でんきだま）。だれにでも出る（でんきだまはピカチュウだけ）。ほかのポケモンの固有技の隠れた材料にもなる。

### 4.5 タイプ相性

## 5. ポケモン

### 5.1 ステータス
- 【決定】各ポケモンに固定ステータスを持たせる。PokeAPI の種族値をゲーム内の数値に変換して自動生成する。
- 【初期案】変換式は調整できるようにデータで定義する。
- 【決定】ステータスの項目:

| ゲーム内のステータス | 元にする種族値 | 内容 |
|---|---|---|
| 最大HP | HP | |
| 物理の威力 | こうげき | 物理の技のダメージに掛かる |
| 特殊の威力 | とくこう | 特殊の技のダメージに掛かる |
| 防御 | ぼうぎょ と とくぼう の**高い方** | 受けるダメージを減らす（雑魚の攻撃は接触だけなので、防御は1つにする。耐久が高い印象のポケモンがそのまま硬くなる） |
| 移動速度 | すばやさ | |
| 取得範囲・HP回復・クールダウン短縮・範囲・発射数・運・経験値倍率など | （種族値なし） | 持ち物・永続強化で上がる |

  原作の技の分類（物理・特殊）とこうげき・とくこうの差が、そのままポケモンごとの得意な技の差になる。
- 【決定】ゲーム内の値 = **ゲームの基準値 × 種族値のランクによる倍率**。600族が強く、進化前が弱いのが当たり前になるようにする。
- 【初期案】受けるダメージ = ダメージ × 100 / (100 + 防御)。敵に触れてダメージを受けた後は短い無敵時間（0.6秒）。レベルが上がるごとに最大HP +2%、威力・防御 +1%（`data/game/stats.json`）。
- 【初期案】ランクは種族値の区切りで決め、区切りと倍率は `data/` で定義する。例:

| 種族値 | 〜49 | 50〜69 | 70〜89 | 90〜109 | 110〜129 | 130〜 |
|---|---|---|---|---|---|---|
| 倍率 | ×0.7 | ×0.85 | ×1.0 | ×1.15 | ×1.3 | ×1.45 |

  基準値は「レベル1のときの値」とし、レベルアップ・進化・持ち物で伸ばす。進化すると種族値が上がるので、ランクも自然に上がる。

### 5.2 進化
- 【決定】進化は必ず起きる（進化しない選択肢はない）。
- 【決定】一定レベルで進化する。進化でステータスが上がり、タイプが変わる・増える場合は技の候補も変わる。
- 【決定】レベルで進化するポケモンは、**原作どおりのレベル**で進化する（例: ヒトカゲ 16 → リザード 36 → リザードン）。
- 【決定】進化の石に意味を持たせる。例: イーブイは、ほのおのいしを持っていればブースターに進化する。同じ石が、御三家などでは固有技の材料にもなる（案A の場合）。
- 【決定】進化の石は、進化したとき・派生（固有技など）したときに**なくなる**（持ち物の枠が1つ空く）。
- 【決定】イーブイのように石で進化するポケモンは、石を持っていなければ進化しない（「進化は必ず起きる」の例外）。協力プレイでは「誰かが持っている持ち物は候補に出ない」ため、例えばホストがイーブイで、ゲスト3人がすべての石を持っていると、イーブイは進化できない。石を誰が持つかを相談する、パーティプレイの要素として受け入れる。
- 【決定】通信交換で進化するポケモン（ゴーリキー → カイリキー、ゴースト → ゲンガーなど）は、持ち物「**つながりのヒモ**」（linking-cord）を持っていると進化する。進化するとなくなる（石と同じ）。ほとんどのポケモンには効果がないので、候補の除外（BAN）の対象になりやすい。
- 【要決定】分岐進化（イーブイ、ニョロゾなど）を扱うか、扱う場合の選び方。カントー版の範囲では必要になるポケモンを確認する。イーブイは「持っている石で進化先が決まる」案がある（上記）。

- 【初期案】出現する種類は時間帯ごとに切り替える（その時間帯の一覧から選ぶ）。前の時間帯の種類の敵は、プレイヤーから離れすぎたら移し替えずに消す（時間帯が進むと前の種類が自然にいなくなり、ストーリーが進んだ感じも出る）。
- 【決定】**一度いなくなった種類は、後の時間帯で再び出さない**（原作の感覚に近づけるため）。続いた時間帯に同じ種類が出るのはよい（例: ポッポが1番道路とトキワの森の両方に出る）。データの読み込み時に検証し、違反していればエラーにする。
- 【初期案】PokeAPI の出現データから一覧を作るときは、各種類を「最初に出てくる区間」から続く区間にだけ割り当てる（原作で後の場所にも出る種類は、後の区間からは外す）。後の区間には、その区間で初めて出る種類と進化形が残る。
- 【決定】カントーでは、原作のストーリーの順に出てくる野生ポケモンを、15分の中で再現する（最初はコラッタ・ポッポ・キャタピーなど）。
- 【決定】原作のバージョン違いは統合する。ストーリーのルート（場所の順番）と各場所の出現確率をまとめて、時間に割り当てる。
- 【初期案】出現の一覧は PokeAPI の出現データ（場所ごと・バージョンごとの出現率）から生成する:
  - 対象のバージョンは 赤・緑・青・ピカチュウ・ファイアレッド・リーフグリーン。PokeAPI のカントーの場所には、金銀・ハートゴールド/ソウルシルバー（3年後のカントー）と Let's Go の出現も入っているため、バージョンで絞る。
  - 各場所で、バージョンごとの出現率を平均して重みにする。一部のバージョンにしか出ないポケモンは、平均すると自然に重みが小さくなる。
  - 草むら・洞窟の出現を基本にし、なみのり・つりの出現は重みを下げて混ぜる。
  - ストーリーの場所の順番と、各区間に割り当てる時間は手書きのデータで決める。
- 【初期案】**レア枠**: その区間までに原作で手に入るが、野生では（ほぼ）出ないポケモンを、ごく低い確率（例: 1%）で出す。倒すと経験値を多く落とす（例: 10倍）。見た目で分かるよう光らせる。候補:
  - バージョン限定のポケモン（平均した重みが一定以下のもの）
  - もらえるポケモン（御三家、イーブイ、ラプラス、エビワラー・サワムラーなど）
  - 化石のポケモン（オムナイト、カブト、プテラ）
  - ゲーム内の交換で手に入るポケモン
  - 通信交換で進化するポケモン（ゴローニャ、ゲンガー、フーディン、カイリキー）は終盤のレア枠にする
  - 伝説・幻はレア枠に入れない（ランクリア後の乱入用）
- 他の地方での再現性（2026年10月時点の PokeAPI で確認）: ホウエン・イッシュ・ガラルには場所ごとの出現データがあり、同じ方法で作れる。**パルデア（スカーレット・バイオレット）は場所はあるが出現データが無い**ため、手書きなど別の方法が必要。ストーリーの場所の順番はどの地方も手書き。
- 【初期案】時間帯の例（中ボスはその区間の終わりに登場）:

| 時間 | 原作の場所の例 | 雑魚の例 | 中ボス |
|---|---|---|---|
| 0:00〜 | 1番道路・トキワの森 | コラッタ、ポッポ、キャタピー、ビードル、トランセル、コクーン | タケシの相棒 |
| 〜 | 3番道路・おつきみやま | オニスズメ、ズバット、イシツブテ、パラス | カスミの相棒 |

- 【決定】（作者の指摘）バンサバ系に合わせ、プレイヤーは最初から敵よりずっと速く、自由に動ける。敵は常にゆっくりで、かわしにくくなるのは**量**のせいにする。序盤の出現はゆっくりにする。
- 【初期案】ヴァンパイアサバイバーズの Mad Forest（0:00 は最低15体・1秒ごと、後半は0.1秒ごと・最低300体など）を参考に、時間帯ごとに「出現数」「最低数（少なければ補充する）」「上限」を決める。1人あたり、最初は毎秒1体・最低15体・上限60、最後の区間は毎秒12体・最低200体・上限450。HP の倍率の伸びはゆるめ（最後の区間で ×4.9）。プレイヤーの速さは180、敵は原作の すばやさ から 37〜69（`30 + すばやさ × 0.35`、上限75）。敵は画面のすぐ外に出す。
- 【初期案】敵の数が少ない分、後の時間帯ほど雑魚の経験値を増やす（×1 → ×3.6。`spawn.json` の `xpMultiplier`）。
- 【初期案】（フェーズ1の仮）上の表の8区間を約112秒ずつにし、雑魚は表の例のポケモン（イワークは中ボスと重なるので外し、チャンピオンロードにゴローンを足す）。中ボスは決まっているタケシ → イワーク（1:52）とカスミ → スターミー（3:45）の2体だけ。ボスは未決定事項4が決まるまで仮にラプラス（範囲技: ふぶき）。値は `data/game/spawn.json`・`enemies.json`・`stage.json`。

## 8. アンロック・実績・永続強化

### 8.1 ポケモンのアンロック
| 対象 | 条件 |
|---|---|
| ジムリーダーの相棒（中ボス） | 【決定】20体撃破 |
| 四天王・サカキの相棒（ボス） | 【決定】10体撃破 |
| 伝説ポケモン | 【決定】5体撃破 |

- 【決定】協力プレイ時、**雑魚以外**（中ボス・ボス・伝説）の撃破は参加者全員にカウントする。
- 【決定】雑魚の撃破は、とどめを刺したプレイヤーにカウントする。
- 【初期案】御三家など最初から使えるポケモンと、それ以外の解放条件。

### 8.2 実績
- 【決定】ランクリア後に乱入した伝説を倒した場合など、達成が難しいものには裏実績を用意する。
- 【初期案】アンロック条件・実績は**データで定義**し、ゲーム中の出来事（撃破・進化・生存時間・技の習得など）を監視して判定する仕組みにする。条件を100個以上に増やしても管理できるようにする。
- 例: 「ほのおタイプの技で敵を1000体倒す」「特定の技の組み合わせを完成させる」など。
- 【決定】倒した敵の数を、実績・アンロックのために記録する。
- 【初期案】ほかに記録する項目（Vampire Survivors の実績を参考に）:
  - 撃破数の内訳: ポケモンの種類別・技別・技のタイプ別・効果ばつぐんで倒した数・状態異常（やけど等）で倒した数・1ランでの最多撃破
  - 中ボス・ボス・伝説をそれぞれ倒した回数
  - ランクリア: ステージ別・使ったポケモン別・人数別（ソロ / 協力）
  - 生存時間（合計・最長）、到達レベル、進化した回数（最終進化への到達）
  - 技: 覚えた技、最大まで強化した技、派生技・固有技の完成
  - 持ち物を取った回数、拾った物（回復など）の数、集めた経験値
  - 協力プレイ: 味方を復活させた回数、協力でのクリア回数
  - 縛りの記録: 技1つだけでクリア、ダメージを受けずに○分生存、見送り・リロールの回数
  - 図鑑の登録数
- 【初期案】記録はラン中は数えるだけにして、ラン終了時（と数分ごと）にまとめて保存する（Firestore の書き込み回数を抑える。`02_architecture.md` 8章）。

### 8.3 コインと永続強化
- 【決定】ラン終了時にコインを獲得し、永続強化に使う。
- 【決定】永続強化には「復活可能数」「リロール数」などを含む。
- 【決定】永続強化は少し有利になる程度にとどめる。初心者と熟練者が一緒に遊んでも構わない。
- 【決定】（2026年10月21日、作者が承認）コインの入り方・強化の一覧と上限・費用・払い戻しは `07_content_draft.md` 10章のたたき台のとおり（値は `data/game/shop.json` で調整する）。
- 【決定】（同日、作者のテストランを受けて）コインが少ない・強化が高いので、**商品と値段はヴァンパイアサバイバーズのパワーアップを参考にする**。【初期案】威力・アーマー・最大HP・クールダウン・範囲・弾速・移動速度・マグネット・ラック・グロース・グリード・復活・リロール・除外の14種類（「回復」は道具のきずぐすりに任せて外した。3.4）。費用は基本の費用 × 次のランク（例: 威力200、復活10000）。コインはクリアで約1700、10分で失敗して約550。前の版の強化は、使ったコインを全額返す。
- 【初期案】永続強化はゲーム内の店（**フレンドリィショップ**）で、ランで集めたコインを使って買う。
- 【初期案】店で買える強化の1つに**候補の除外（BAN）**を入れる。レベルアップの選択画面で、出てきた候補を除外すると、その技（持ち物）はそのランでは二度と候補に出ず、代わりの候補を引き直す。除外できる回数を店で増やす（Vampire Survivors の Banish と同じ）。複数のタイプを持つポケモンで欲しい技を引くために、ランを周回してコインを集め、除外の回数を買いたくなる流れを作る。
- 【決定】除外はラン中に使う回数制（上記）にする。

### 8.4 図鑑・見た目
- 【初期案】倒した敵・使ったポケモンを図鑑に登録する。
- 【初期案】色違いなどの見た目の報酬。寄付とは無関係にゲーム内で解放する。

## 9. 操作（PC）

- 【初期案】移動: WASD / 矢印キー。技は自動発動。ポーズ: Esc。
- 【決定】協力プレイではホストだけがポーズできる（全員のゲームが止まる）。ホスト以外が Esc を押したときは、ゲームを止めずに設定などの画面だけを出す。
- 【初期案】レベルアップ時の選択: マウス、または数字キー。リロール・見送るにもキーを割り当てる。
- 【要決定】ゲームパッド対応の有無。

## 10. やらないこと

- ランキング
- 途中参加
- 5人以上の協力プレイ
- 観戦
- 対戦（PvP）
- リプレイ（ランの録画・再生）
- 課金・広告・寄付者特典
- 公式の音楽・公式の背景素材の使用
